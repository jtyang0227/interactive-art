# 다음 인터랙티브 기능 기획

**작성일**: 2026-09-02
**방법**: 현재 코드/README Status 대조 + Gemini(`gemini-3.6-flash`) 독립 브레인스토밍 종합

## 한 줄 요약

기존 파티클/타이포그래피 인터랙션 시스템을 "확장"하는 방향으로 6개 후보를 추립니다.
카메라 웹캠·실시간 멀티유저 같은 개인정보·인프라 이슈가 있는 아이디어는
(기존 오디오 반응형과 동일한 논리로) 보류 목록에 남겨둡니다.

## 후보 기능 목록

### 1. 커서 아래 깊이 렌즈 효과 (Sub-surface Depth Push / Lensing) — ✅ 구현 완료
- **설명**: 마우스가 파티클 위에 있을 때, 기존 반발(repulsion) 로직에 더해 커서 아래 파티클들의 Z축 깊이를 살짝 밀어내고 확대되는 듯한 렌즈 왜곡을 준다.
- **왜 필요한가**: `particle.vert.glsl`에 이미 있는 `uPointer`/`uPointerActive` 반발 로직을 그대로 확장하는 것이라 구현 리스크가 가장 낮으면서, "마우스가 공간을 조종한다"는 기획서 3항 목표를 시각적으로 더 강화한다.
- **예상 난이도**: 낮음
- **선행 조건**: 없음 (새 셰이더 유니폼 1~2개만 추가)

### 2. 잔상/기억 레이어 — 마우스 궤적 + 이전 키워드 (Ghost Trail & Echo) — ✅ 구현 완료

**(b) 이전 키워드 에코.** 키워드가 바뀔 때마다 직전 단어를 별도의 저밀도(약 30%)·
저채도 파티클 레이어로 다시 샘플링해 같은 파티클 셰이더를 재사용, `uGlobalAlpha`라는 새 유니폼으로
1.2초 페이드인 → 유지 → 11초에 걸쳐 페이드아웃시킴. 클릭/포인터에는 반응하지 않는 순수 배경 레이어.

**(a) 마우스 궤적 잔상.** 렌더 타겟 방식 대신, `WorldGroup`이 최근 포인터 위치 16개를 원형 버퍼로
유지하며(0.05초 간격 샘플링) 각 지점의 나이(age)와 함께 셰이더에 유니폼 배열(`uTrailPoints`,
`uTrailAges`)로 전달하는 가벼운 방식을 택함. 정점 셰이더에서 16개 지점에 대한 거리·나이 기반
감쇠를 합산해 커서가 실제로 지나간 경로를 따라 파티클이 잠시 끌려나왔다가 서서히 복귀함.

- **설명**: (a) 마우스가 지나간 자리에 파티클 움직임이 옅게 남는 것(기획서 8항, 이번 세션 초반에 GPGPU 복잡도 때문에 보류했던 항목)과 (b) 이전에 입력했던 키워드가 아주 희미하게 배경에 겹쳐 남아있다가 서서히 사라지는 것(Gemini 제안 #10)을 "기억" 테마로 묶어서 구현.
- **왜 필요한가**: "언어가 물질이 되는 것을 시적으로 시각화한다"는 기획서의 핵심 주제와 가장 직접적으로 맞닿아 있고, 키워드 입력 기능(이번 세션에 추가)과 자연스럽게 이어진다.
- **예상 난이도**: 중간~높음 (렌더 타겟 ping-pong 방식의 가벼운 트레일 텍스처, 또는 별도 저밀도 파티클 레이어 + 히스토리 버퍼 필요 — `AtmosphereField`와 비슷한 패턴 재사용 가능)
- **선행 조건**: 없음 (새 의존성 불필요)

### 3. 멀티터치 비틀기 + 핀치 밀도 조절 (Multi-touch Torsion & Pinch)
- **설명**: 두 손가락으로 비틀면 공간에 소용돌이(vortex) 힘이 가해지고, 핀치하면 파티클 샘플링 밀도가 압축/확장된다.
- **왜 필요한가**: 기획서 16항(Responsive)에 명시된 모바일 입력 중 "Swipe" 계열이 아직 없음 — 현재 터치는 한 손가락 드래그(회전)와 탭만 지원. 멀티터치는 드래그 회전과 제스처가 겹치지 않아 충돌 없이 추가 가능.
- **예상 난이도**: 중간
- **선행 조건**: 없음

### 4. 모바일 자이로스코프 중력장 (Gyroscope Gravity Vector)
- **설명**: 기기를 기울이면 그 방향으로 파티클이 서서히 쏠리는 힘을 curl-noise 흐름장에 더한다.
- **왜 필요한가**: 데스크톱의 마우스 무브 인터랙션에 대응하는 모바일 전용 "공간이 반응한다" 경험을 제공. 구현이 간단함.
- **예상 난이도**: 낮음
- **선행 조건**: 없음 (단, iOS 13+에서는 `DeviceOrientationEvent.requestPermission()` 사용자 동의 프롬프트 UI가 별도로 필요 — 기획서의 "UI 최소화" 원칙과 약간 긴장 관계이니 진행 시 별도 확인)

### 5. 미세한 속도 기반 색수차 (Subtle Velocity Chromatic Dispersion)
- **설명**: 파티클이 고에너지 상태(클릭 리플, 드래그 버스트)일 때 아주 살짝 RGB가 갈라지는 느낌을 순간적으로 준다.
- **왜 필요한가**: 기획서 12항에 "Chromatic Aberration"이 효과 후보로 명시되어 있음. 단, "모노크롬 시각 언어" 원칙과 정면충돌할 위험이 커서 **아주 미세하게, 고에너지 순간에만** 적용해야 함.
- **예상 난이도**: 낮음 (셰이더 로직만)
- **선행 조건**: 없음. **디자인 리스크 주의** — 과하면 기획서가 명시적으로 금지한 "무지개 그라데이션"처럼 보일 수 있음.

### 6. 햅틱 펄스 (Haptic Feedback)
- **설명**: 클릭 리플이나 드래그 버스트 같은 고에너지 이벤트에 맞춰 `navigator.vibrate()`로 짧은 진동을 준다.
- **왜 필요한가**: 구현 비용이 거의 0에 가까운 모바일 폴리시 항목.
- **예상 난이도**: 낮음
- **선행 조건**: 없음. **단, iOS Safari는 Vibration API를 지원하지 않음** — Android Chrome 등에서만 동작, 자동으로 no-op 처리되도록 구현 필요.

## 권장 우선순위

1. **커서 깊이 렌즈** — 리스크 최소, 기존 로직 확장이라 가장 빠르게 완성도 확인 가능
2. **잔상/기억 레이어** — 작품의 핵심 주제와 가장 강하게 연결되는 항목이라 다음 "의미 있는" 단계로 추천
3. **멀티터치 비틀기/핀치** — 기획서에 명시됐지만 아직 없는 모바일 입력을 채움
4. **모바일 자이로스코프**
5. **미세 색수차** (디자인 검토 후 진행 — 시안을 먼저 보고 톤 확인 권장)
6. **햅틱 펄스** (아무 때나 곁들여도 되는 저비용 항목)
